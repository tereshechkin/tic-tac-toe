## 📋 О проекте

Данный проект **не имеет бизнес-ценности**, однако обладает **высокой методологической ценностью** как демонстрация полного цикла разработки enterprise-решения с нуля. Проект создан с целью:

### 🎯 Анализ LLM-моделей
- Сравнение **рассуждающих** (o4-mini, o3-pro, gpt-4o) и **не рассуждающих** моделей (gpt-5.4, gpt-4.1) в контексте игровой задачи;
- Оценка стоимости, доступности, скорости ответа и качества решений;
- Сбор статистики эффективности для дальнейшего анализа.

### 📐 Формирование шаблонов проектной документации
- Полный цикл документирования: от требований до архитектуры;
- Подробные спецификации API (OpenAPI);
- Sequence-диаграммы для критических сценариев;
- Документация по развертыванию и мониторингу.

### 🧩 Шаблоны технических решений

#### Frontend
- **Лендинг с высокой конверсией**: SEO-оптимизация (meta-теги, микроразметка, OpenGraph), адаптивный дизайн, LCP < 1.5с;
- **Система дизайна**: Light/Dark темы с сохранением в профиле;
- **Стейт-менеджмент**: Zustand + React Query для кэширования и синхронизации;
- **Асинхронные обновления**: WebSocket для real-time игрового процесса;

#### Backend
- **Аутентификация и авторизация**: JWT (access 15 мин, refresh 30 дней), OAuth 2.0 (VK, Google), email-верификация;
- **Безопасность**: Rate limiting (5/час на регистрацию, 10/мин на логин), защита от CSRF/XSS/SQL-инъекций, блокировка после 5 неудачных входов;
- **Масштабируемость**: Горизонтальное масштабирование, сессии в Redis, репликация БД, очереди RabbitMQ;
- **Производительность**: TTFB < 300 мс, поддержка 100+ сессий на инстанс, оптимизация запросов (индексы, кэширование);

#### Инфраструктура
- **Наблюдаемость**: ELK Stack (логи), Prometheus + Grafana (метрики), алерты по критическим событиям;
- **Отказоустойчивость**: Circuit Breaker для LLM API, Graceful shutdown, автоматический перезапуск, RTO < 1ч, RPO < 5 мин;
- **CI/CD**: GitHub Actions, Docker контейнеризация, Zero-downtime деплой;

#### Архитектурные паттерны
- **Адаптеры LLM**: Универсальный интерфейс для подключения любых моделей;
- **Асинхронная обработка**: RabbitMQ для длительных задач (ходы LLM);
- **CQRS**: Разделение на команды (ходы) и запросы (статистика);
- **Event Sourcing**: История игр как последовательность событий;

## 🎮 Функциональные возможности

### Для пользователей
- ✨ Игра против **9 LLM-моделей** разных типов (рассуждающие/без рассуждения);
- 🎯 Настраиваемое поле: **3×3, 5×5, 10×10, 30×30**;
- 🏆 Победные последовательности: **3, 4, 5** символов;
- 👥 Игра с **другими игроками** по коду сессии;
- 📊 Личный кабинет с **детальной статистикой** и историей;
- 📤 Экспорт истории в **CSV/JSON**;
- 🌓 **Light/Dark** темы оформления;
- 🔐 Вход через **Google, VK ID** или email;

### Для администраторов
- 🛠️ Админ-панель для управления пользователями и моделями;
- 📈 Панель мониторинга состояния LLM-сервисов;
- ⚡ Управление моделью (включение/отключение);
- 🔍 Полный доступ к игровым сессиям и метрикам;


## 📈 Мониторинг и алерты

### Доступные дашборды
- **Grafana**:
  - Метрики производительности (CPU, RAM, Network)
  - Время отклика LLM-моделей
  - Активные сессии и ходы в секунду
  - Бизнес-метрики (DAU, MAU, популярность моделей)

- **Kibana**:
  - Централизованный сбор логов
  - Поиск и фильтрация по Request-ID
  - Анализ ошибок и предупреждений

### Настроенные алерты
- 🚨 Падение сервиса (health check failed)
- ⏱️ Задержка LLM > пороговых значений
- ❌ Частота ошибок 5xx > 5%
- 💾 Redis memory usage > 80%
- 📉 Свободное место на диске < 20%

## 🎯 Сценарии критических путей

1. **Регистрация → Верификация → Вход → Игра → Сохранение статистики**
2. **Анонимная игра → Восстановление через 12 часов (Cookie)**
3. **Зарегистрированный пользователь → Возврат в игру через неделю**
4. **Ход игрока → Ход LLM (асинхронно через RabbitMQ)**
5. **Отказ LLM API → Circuit Breaker → Fallback**
6. **Graceful shutdown → Восстановление сессий при перезапуске**

## 🧠 Архитектурные решения

### Почему FastAPI?
- Высокая производительность (на уровне Node.js/Go);
- Автоматическая генерация OpenAPI документации;
- Встроенная валидация через Pydantic;
- Асинхронная поддержка для работы с I/O операциями;

### Почему React + TypeScript?
- Строгая типизация для надежности;
- Компонентный подход для переиспользования;
- Богатая экосистема (React Query, Zustand, TailwindCSS);
- Возможность SSR/SSG для SEO-оптимизации;

### Почему RabbitMQ?
- Надежная доставка сообщений (persistent queues);
- Поддержка сложных маршрутов (topics, headers);
- Интеграция с Circuit Breaker для LLM;
- Легкое горизонтальное масштабирование;

### Почему Redis?
- Скорость работы в памяти (state, sessions);
- Встроенные механизмы TTL для анонимных сессий;
- Поддержка Pub/Sub для real-time обновлений;
- Rate limiting через INCR + EXPIRE;
