# WebSocket API для игровых сессий

## Общее описание

WebSocket-соединение используется для получения обновлений игрового состояния в реальном времени и отправки ходов без необходимости повторных HTTP-запросов. Все сообщения передаются в формате **JSON**.

## Подключение

**URL:** `ws://<host>/ws/games/{session_id}`  
**Метод:** WebSocket (RFC 6455)  
**Параметры пути:**
- `session_id` (UUID) — идентификатор игровой сессии, полученный при создании игры через `POST /api/v1/games`.

**Заголовки при рукопожатии (опционально):**
```
Authorization: Bearer <access_token>
```
Если токен не передан, соединение считается гостевым. В этом случае доступ к сессии возможен только при наличии правильного `session_id`.

**Пример подключения (JavaScript):**
```javascript
const ws = new WebSocket(`ws://localhost:8000/ws/games/${sessionId}`);
```

## Формат сообщений

Все сообщения имеют общую структуру:
```json
{
  "type": "string",  // тип события
  "data": {}          // данные, специфичные для типа
}
```

## События от сервера → клиенту

Сервер может отправлять следующие типы сообщений в любой момент.

### 1. `game_state` — полное состояние игры
Отправляется сразу после установки соединения, а также после каждого изменения состояния (ход, завершение).

```json
{
  "type": "game_state",
  "data": {
    "session_id": "uuid",
    "board": [["X"|"O"|null]],
    "board_size": 3|5|10|30,
    "win_sequence": 3|4|5,
    "game_mode": "computer"|"friend",
    "status": "waiting"|"in_progress"|"finished",
    "current_turn": "X"|"O"|null,
    "player_x_name": "string",
    "player_o_name": "string",
    "model_id": "uuid|null",
    "difficulty": "easy"|"medium"|"hard"|null,
    "winner": "X"|"O"|"draw"|null,
    "winning_cells": [[row, col], ...] | null,
    "move_count": number,
    "created_at": "datetime",
    "updated_at": "datetime",
    "finished_at": "datetime|null",
    "move_history": [
      { "player": "X"|"O", "row": number, "col": number, "timestamp": "datetime" }
    ]
  }
}
```

### 2. `move_made` — уведомление о совершённом ходе
Присылается после каждого хода (как игрока, так и компьютера).

```json
{
  "type": "move_made",
  "data": {
    "player": "X"|"O",
    "row": number,
    "col": number
  }
}
```

### 3. `game_over` — игра завершена
Присылается, когда определён победитель или наступила ничья.

```json
{
  "type": "game_over",
  "data": {
    "winner": "X"|"O"|"draw",
    "winning_cells": [[row, col], ...] | null
  }
}
```

### 4. `computer_thinking` — компьютер обдумывает ход
Отправляется перед тем, как сервер запросит ход у LLM. Можно использовать для отображения индикатора загрузки.

```json
{
  "type": "computer_thinking",
  "data": {}
}
```

### 5. `error` — ошибка
Присылается в ответ на некорректное сообщение от клиента или при нарушении логики игры.

```json
{
  "type": "error",
  "data": {
    "message": "Описание ошибки"
  }
}
```

### 6. `exit` — подтверждение выхода
Отправляется после получения клиентского сообщения `exit`.

```json
{
  "type": "exit",
  "data": {
    "message": "Game exited"
  }
}
```

## Сообщения от клиента → серверу

Клиент может отправлять следующие типы сообщений.

### 1. `make_move` — совершить ход
```json
{
  "type": "make_move",
  "player": "X"|"O",
  "row": number,
  "col": number
}
```
**Примечание:** Сервер проверит, что ход допустим (клетка свободна, сейчас очередь данного игрока). В случае ошибки будет отправлено `error`.

### 2. `request_computer_move` — запросить ход компьютера
Используется только в режиме `computer`. Сервер проверит, что сейчас ход компьютера (обычно `O`).
```json
{
  "type": "request_computer_move"
}
```

### 3. `restart` — перезапустить игру с теми же параметрами
```json
{
  "type": "restart"
}
```
После этого сервер сбросит доску, статус и пришлёт новое состояние.

### 4. `exit` — выйти из игры
Сохраняет текущее состояние игры как незавершённое (чтобы можно было вернуться позже). После отправки этого сообщения сервер закроет соединение.
```json
{
  "type": "exit"
}
```

## Пример сценария (режим «Компьютер»)

1. **Клиент создаёт игру** через `POST /api/v1/games` → получает `session_id`.
2. **Подключается** по WebSocket к `ws://.../ws/games/{session_id}`.
3. **Сервер отправляет** `game_state` с начальной доской (ход `X`).
4. **Клиент делает ход** → отправляет `make_move` (игрок `X`).
5. **Сервер валидирует**, обновляет состояние, отправляет:
   - `move_made`
   - `game_state` (обновлённое)
6. Если игра не завершена и сейчас ход компьютера (`O`), сервер **автоматически** инициирует запрос к LLM (без отдельного сообщения от клиента). При этом сначала отправляется `computer_thinking`.
7. **Компьютер делает ход** → сервер обновляет состояние и отправляет:
   - `move_made`
   - `game_state`
8. Если игра завершена (победа/ничья), дополнительно отправляется `game_over`.
9. Игрок может в любой момент отправить `restart` или `exit`.

## Коды закрытия соединения

| Код | Описание |
|-----|----------|
| 1000 | Нормальное закрытие (по инициативе клиента или сервера) |
| 1008 | Игровая сессия не найдена (попытка подключения к несуществующему `session_id`) |
| 1011 | Внутренняя ошибка сервера |

---

## Восстановление соединения

- Если WebSocket разорван, клиент может **переподключиться** к тому же `session_id`.
- Сервер при повторном подключении отправит актуальное состояние игры (`game_state`).
- Активные игры хранятся в Redis **24 часа**, поэтому даже после перезапуска сервера сессия восстанавливается.

---

## Важные замечания

- Все поля `datetime` передаются в формате ISO 8601 (например, `2026-01-01T12:00:00Z`).
- Поле `board` — двумерный массив, где `null` означает пустую клетку.
- В режиме `friend` компьютер не участвует, и ходы делают оба игрока через WebSocket.
- В режиме `computer` сервер самостоятельно запрашивает ход у LLM, клиенту не нужно вызывать `request_computer_move` (этот вызов зарезервирован для ручного управления, но в текущей реализации не обязателен).

## Схема данных (GameState)

Полное описание структуры `GameState` соответствует ответу REST-эндпоинта `GET /api/v1/games/{session_id}`. Для удобства приведём её здесь:

```typescript
interface GameState {
  session_id: string;            // UUID
  board: ("X" | "O" | null)[][];
  board_size: 3 | 5 | 10 | 30;
  win_sequence: 3 | 4 | 5;
  game_mode: "computer" | "friend";
  status: "waiting" | "in_progress" | "finished";
  current_turn: "X" | "O" | null;
  player_x_name: string;
  player_o_name: string;
  model_id: string | null;
  difficulty: "easy" | "medium" | "hard" | null;
  winner: "X" | "O" | "draw" | null;
  winning_cells: [number, number][] | null;
  move_count: number;
  created_at: string;
  updated_at: string;
  finished_at: string | null;
  move_history: Array<{
    player: "X" | "O";
    row: number;
    col: number;
    timestamp: string;
  }>;
}
```
